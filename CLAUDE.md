# SozvonAI

## Что за проект
SaaS-сервис для автоматической транскрибации деловых звонков и встреч. Пользователь (предприниматель) загружает аудио/видео встречи, сервис расшифровывает речь в текст.

## Для кого
Предприниматели и бизнесмены, проводящие переговоры и деловые встречи, которым нужна текстовая расшифровка без ручного конспектирования.

## Стек
- Backend: Python 3.11 + FastAPI (отдельный venv в `backend/`, не путать с окружением `tools/claude-memory-compiler`)
- ASR: faster-whisper (small, GPU/CUDA основной путь, CPU int8 — fallback) — без платных API, ключевое требование
- VAD: silero-vad (CPU)
- Диаризация: гибрид — грубая live (эмбеддинги + онлайн-кластеризация, CPU) + точная offline (pyannote.audio, GPU/CUDA) с реконсиляцией после звонка
- Аудио-конвертация: ffmpeg (для видеозаписей звонков)
- Видео-инсайты: `yt-dlp` (скачивание YouTube-аудио) + локальная LLM для суммаризации (Qwen2.5-3B-Instruct, GGUF, CPU через `llama-cpp-python`) — без платных API
- Хранение: SQLite (метаданные/транскрипты) + локальный диск (аудиофайлы), без базы знаний/RAG
- Real-time транспорт: WebSocket
- Платформа деплоя: не выбрана, сейчас локальная разработка

Полная архитектура и обоснование решений — `docs/architecture.md`.

## Текущий статус
Все 4 стадии MVP звонков (batch, live-мик, захват онлайн-звонков, реконсиляция+полировка) реализованы и проверены — на синтетике и на реальном голосе пользователя (включая реальные баги live-диаризации, найденные и исправленные 2026-09-26). Плюс отдельный раздел "Видео-инсайты" (Stage 5).
- Stage 1: `POST /calls/upload` → ffmpeg → faster-whisper (GPU) → pyannote-диаризация (GPU) → SQLite → `GET /calls/{id}`.
- Stage 2: `WS /ws/stream/{call_id}` + `static/live.html` — микрофон → VAD (silero-vad) → потоковый whisper → грубая live-диаризация (resemblyzer + онлайн-кластеризация) → текст на экране почти в реальном времени.
- Stage 3: захват онлайн-звонков (`getDisplayMedia` + микс с микрофоном) — подтверждено на реальном тесте (вкладка + мик одновременно).
- Stage 4: фоновая реконсиляция черновой live-диаризации точным offline pyannote после звонка, экспорт (txt/pdf/аудио), список звонков, переименование спикеров.
- Stage 5: "Видео-инсайты" (`static/videos.html`/`video.html`) — ссылка на YouTube → `yt-dlp` → faster-whisper (автоопределение языка) → отчёт по ключевым мыслям локальной LLM (CPU). Не связано с моделью данных звонков.
- Требуется `HF_TOKEN` в `backend/.env` (бесплатный, для pyannote).
- Требуется модель для видео-инсайтов в `backend/.tools/models/` — см. `docs/tasks.md` (Stage 5).
- Визуальный редизайн (современный SaaS, цветовая разметка реплик по спикерам) сделан 2026-09-25.
- UX-полировка `calls.html` (2026-09-26): более плотная вёрстка, кнопка удаления записи (`DELETE /calls/{id}`) с авто-сверкой базы с диском при каждом обновлении списка (ручное удаление папки в проводнике больше не оставляет "осиротевших" записей), кнопка/путь к папке хранения записей, фавикон.
См. `docs/status.md`, `docs/issues.md`.

## Расширение: "Видео-инсайты" (2026-09-25 решение принято, 2026-09-26 реализовано)
Второй раздел приложения (не подмешивается в модель данных звонков) — пользователь вставляет ссылку на видео, сервис скачивает аудио, расшифровывает и делает отчёт по ключевым мыслям. Отдельный джоб от бизнес-звонков: там приватный разговор + разметка по спикерам, здесь публичный контент + суммаризация смысла (диаризация не нужна, обычно один рассказчик).
- Платформы: сейчас только YouTube (`yt-dlp`) — Instagram/Telegram сознательно отложены (ToS/техническая хрупкость).
- Суммаризация — через локальную LLM (не платный API) — согласуется с принципом "без платных API", распространённым здесь и на текст, не только на аудио. Модель — Qwen2.5-3B-Instruct (GGUF), CPU через `llama-cpp-python`; подробности установки — `docs/tasks.md` (Stage 5).
- Это не отменяет и не пересматривает решения по звонкам ниже — это отдельная, аддитивная фича.
- Идеи на будущее (не решено, не начато): Instagram/Telegram как источники, чанкинг очень длинных видео вместо обрезки транскрипта по лимиту контекста LLM — см. `docs/ideas.md`.

## Решения, которые уже приняты и не пересматриваются
- Транскрибация — только локальный Whisper (faster-whisper), платных API транскрибации не используем
- В MVP нет базы знаний / сложной аналитики — только цикл "звонок → транскрипт по спикерам"
- Источники звука: очные встречи (микрофон) + онлайн-звонки (захват вкладки браузера live, либо загрузка готовой записи batch) + загрузка любого файла как universal fallback
- Режим — real-time streaming (не только batch); диаризация — обязательна, но реализуется гибридно: черновая live-разметка спикеров + точная пересборка pyannote после звонка (полноценная live-диаризация технически ненадёжна, это осознанный компромисс)
- Железо — GPU (CUDA) как основной путь инференса для ASR и offline-диаризации (на машине есть NVIDIA GTX 1650, 4GB VRAM — этого достаточно для faster-whisper small и pyannote); CPU int8 с откатом на модель `base` остаётся конфигурируемым fallback-путём (важно для будущего деплоя на сервер без GPU)
- Порядок реализации фиксирован: сначала Stage 1 (batch, без стриминга) для проверки качества ASR/диаризации, и только потом live-стриминг — так рискованная часть (real-time) не блокирует проверку ядра
- Платформа деплоя пока не выбрана — сначала локальная разработка, вопрос сервера/облака решается позже
- Одновременно — один активный live-звонок, аутентификация/multi-user — вне MVP
